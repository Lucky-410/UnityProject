## 1. 目标与范围

将当前 GameScene 的旧环境视觉整体替换为统一的暗黑幻想像素场景。保留已经验证的玩法骨架，用地形厚度、建筑结构、自然轮廓、空间层次和环境组合提升完成度。

- 新环境素材仅从 PixelPlatformerSet1v.1.1、PixelFantasy_Caves_1.0、DarkForest1.2 中选用；允许从这些素材提取可平铺纹理、创建 Tile、SpriteShape Profile 和环境 Prefab。
- Tilemap、SpriteShape、独立精灵必须各自实际参与最终画面，不能放空对象充数。
- 保留路线、重要平台高度与间距、出生点、门、遭遇战、触发器、相机限制和脚本引用。需要调整时先说明依赖并提交具体变更。
- 保留当前 W 跳跃、J 唯一攻击键及移动、冲刺参数。本轮不扩展战斗、Boss AI、道具系统，也不重做 UI 或角色动画。
- 新增代码注释、可见 UI 使用中文；文件、Prefab、Hierarchy 名称可以使用英文。
- 不承诺通过美术重建达到 5–8 分钟时长；当前路线长度与战斗内容保持原有规模。

## 3. 总体路线与五段构图

主题：**被森林吞没的古代遗迹，通向岩层中的地下祭坛。** 利用洞口、破墙与岩石侵入建筑的过程完成转换；不改变玩家路线为真正的下行关卡。

```text
左 → 右（沿用玩法路线）
荒林外围 ─ 石门入口 ─ 残破回廊 ─ 根蚀岩窟 ─ 地下祭坛
  古树       拱门        断柱        顶壁        主拱与双柱
══════════════ 可行走表面与原有平台 ═════════════════
  厚土/根系 → 石砌地基 → 破损墙基 → 岩层 → 祭坛基座
  远林与天空 → 门后暗部 → 破墙洞口 → 深洞 → 后殿剪影
```

下列坐标来自已有路线记录，实施前以 Unity 实测确认，不能用记录覆盖当前对象。

| 区域 | 现有范围（世界 X） | 画面焦点与结构 | 密度与落地要求 |
|---|---|---|---|
| A 荒林外围 | -4～1.8 | 一棵偏侧古树、远林、断墙，草皮下露出土层与根系 | 出生区域清晰；树根嵌入土中，断墙有基脚，远景留出天空 |
| B 石门入口 | 1.8～6 | 石门框出后方暗部，树根侵入石墙，局部暖光 | 作为样板区；柱脚、门槛、墙体连续，灯具连墙或吊架 |
| C 残破回廊 | 6.35～10.8 | 断柱与侧墙形成节奏，墙后可见洞穴；保留 x≈8.2 平台 | 战斗带降低细节密度；悬挑平台加托石或柱座，不改变可站高度 |
| D 根蚀岩窟 | 11.15～16.4 | 顶壁压低空间感，岩柱贯穿背景，保留 x≈13.35 平台 | 钟乳石接顶，石笋接地；冷色岩层中仅少量异常色光 |
| E 地下祭坛 | 16.75～24.5 | 宽阔中央战斗区，后方大拱、两侧残柱与阶式基座 | 中央留白；两侧半对称，中央背景低对比，不制造假可站台阶 |

现有地面顶面约为 Y=-0.6，回廊约 -0.45；这些是核对基准，最终以现有 Collider 为准。三个约 0.35 的断口保留跳跃间距，画出两侧断崖、侧壁与后方洞腔，不增加跨越断口的实体碰撞。

复杂度来自厚地形、上下空间、远近遮挡和成组叙事细节。每个区域设置一个主焦点、两组以内次要环境组合，并保留可读的行走与战斗带；不通过密集随机撒物件增加复杂度。

## 4. 三种搭建方式的明确分工

| 技术 | 必须实际完成的内容 | 碰撞与约束 |
|---|---|---|
| Tilemap | 主地面、平台、厚土与岩石填充、建筑墙体与地基 | 主地面/平台用 TilemapCollider2D + CompositeCollider2D + Static Rigidbody2D；背景墙无碰撞 |
| SpriteShape | 荒林下方不规则崖体、岩窟外轮廓、局部前景根岩剪影 | 至少覆盖森林与洞穴两个区域；默认仅视觉，无碰撞。使用可平铺填充与短折线/受控切线，避免像素被拉长 |
| 独立精灵 | 古树、岩柱、门拱、碎石组合、灯具、旗布和大构件 | 以接地/接墙/接顶锚点放置；重复组合做 Prefab；不用于逐块拼主地面 |

Tilemap 根据真实用途创建 Ground、Platform、Background、Decoration_Back、Decoration_Front。没有危险玩法时不增加假危险瓦片；不为了目录完整创建空 Hazard 层。

RuleTile 只用于具有完整边角与中心块的地形族；缺少内角或特殊构件时使用明确普通 Tile 补位。自然 SpriteShape 若出现明显拉伸，调整为低曲率轮廓与像素平铺填充，再用岩石/根系精灵遮接缝；仍须保留可见且合格的 SpriteShape 用途。

## 5. 地形厚度与支撑规则（硬性验收）

1. **主地面不是薄条。** 草皮/石面以下必须连续出现侧面、内部填充、根系或岩层，延伸至该处允许相机视野底部以下至少两个已确认的地形瓦片高度；所有合法相机位置均不能露出填充底边。
2. **断口有空间解释。** 两侧有垂直岩壁或断裂地基，下方是分层洞腔，不能只有地表悬在纯色空背景上。远景洞腔不提供碰撞。
3. **平台有承重解释。** 现有高台用石柱、托石、岩体连接或有两端支撑的木构实现；支撑视觉不得偷偷改变原可穿行区域。
4. **锚点按可见像素确定。** 不仅依赖含透明边缘的 Sprite Bounds。树根、箱底、柱脚至少贴合或轻微嵌入承载面；钟乳石、吊灯分别接顶或接链条。
5. **物品与交互点有落脚处。** 掉落和奖励生成点下方存在有效可站表面，不在断口或墙体内；已有悬浮拾取动画可保留，但其底座/地面投影或光效须说明悬浮状态。
6. **装饰不伪装成路线。** 背景台阶、远处桥梁降低对比并与主路线错开；没有碰撞的平台不能使用同样明亮的可站顶边误导玩家。
7. **不自动修正玩法。** 若检查发现原奖励点、出生点或 Collider 已有问题，记录具体对象与最小修正方案，在阶段报告说明后处理；不得默默改动整条路线。

## 6. 统一画面与可读性

- 主色：炭灰、冷蓝灰、低饱和苔绿；局部火光使用暗金暖橙。异常区域少量暗紫点缀，不把整个画面染紫。
- 明度顺序：远景低对比 → 中景略清晰 → 地表边缘清楚 → 玩家、敌人、攻击提示最易辨识。不能靠压黑掩盖拼接或空洞。
- 至少四层：远景天空/洞穴深处、中景森林/墙体、玩法地面与角色、边缘前景剪影。前景避开跳跃落点和战斗中心。
- 整张背景不能任意拉宽铺满全图。仅在边界能平铺时重复，否则使用分段取景和接缝遮挡；月亮与显著建筑焦点不重复。
- 视差幅度先小后调，明确各系数代表随镜头位移的比例；不直接套用不同脚本含义相反的参数。检查反向移动和边界是否露底。
- 纹理使用 Point，避免有损压缩破坏像素。先用角色、地砖、门框同屏对照确定像素密度；禁止用任意非均匀 Transform 缩放强拼尺寸。
- 相机保持现有构图与限制，评估 Pixel Perfect 与 Cinemachine 的配合后启用合适设置，不能为统一像素比例破坏视野或角色尺寸。
- 沿用现有 Sorting Layer；检查 URP 2D 灯光 Target Sorting Layers，防止新增环境或角色变黑。灯光采用少量分区光和局部灯具，样板阶段确定亮度，不新增几十盏实时灯。
- 环境动态只选轻雾、落叶或灰尘、局部火星；每区选择一到两种，战斗区域减少粒子，不能遮住弹道与受击表现。

## 7. 通过标准与审批节点

### 样板审批（Phase 2 后强制停止）

完成石门入口及相邻森林过渡，约 X=0～6。截图必须同时看见：厚地形、真实 Tilemap、可见 SpriteShape 轮廓、落地的独立精灵、前后景与灯光。提供正常游戏镜头截图及地形下部/结构检查图，说明实际使用的素材。静态设计草图不能代替 Unity 样板验收。

### 全图验收

- 五个区域各一张正常游戏镜头图，另有全景和断口/平台支撑近景；画面不能只挑没有问题的位置。
- 无悬空道具、断开的树根/柱脚、重复月亮、裸露填充底边、无解释的薄平台；不存在用全黑遮住未完成区域。
- 森林、石门、洞穴、祭坛有可辨识的构图变化，过渡连续，地面可走性清楚。
- 完整走图确认 W 跳跃、J 攻击、冲刺、落地、门锁、敌人出生、奖励、相机和既有玩法正常。
- 无新增项目 Error；既有 MCP 连接错误与游戏错误分开记录。未实现的 Boss/胜利系统标为未实现，不能填“通过”。
- 自动检查只验证结构与规则；美观程度以实际 Unity 截图和用户审批为准。
