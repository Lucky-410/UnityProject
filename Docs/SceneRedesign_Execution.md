## 1. 执行边界

- 收到明确批准后才通过 Unity MCP 修改项目；本次交付文档不修改场景、脚本、Prefab 或导入设置。
- 每次最多执行 1–2 个 Phase，到指定关口保存、报告、停止，等待下一步指令。一次批准不取消后续停点。
- 操作正式 `Assets/Scenes/GameScene.unity`，保留原玩法对象及引用；美术根节点和子对象可重建。
- 不继续润色被否决的旧场景。新的环境构建流程必须隔离旧 `RelicfallPhase8Builder`：新入口不得调用旧环境生成逻辑，旧入口应明确标记为旧版并防止误覆盖新场景。
- 不删除原素材包或无关资源；旧视觉从正式场景移除，回滚副本保留。

## 3. Phase 1：基线、备份、素材规格

### 3.1 先读取，再建立清单

通过 MCP 检查 Hierarchy、组件和引用，将对象标记为玩法关键、纯视觉、混合对象。混合对象只替换视觉子层，不直接删除整个父对象。

重点核对 Player、CombatRoom/RoomEncounter、EnemySpawner、SpawnLeft/Right、DoorLeft/Right、RewardMarker、对象池、Main Camera、Player Follow Camera、Confiner 及平台 Collider。Checkpoint、Boss Trigger 等以实际存在为准，不能凭旧文档假定存在。

记录出生点、门和平台 Transform、碰撞边界、相机范围、脚本序列化引用、移动参数、W/J 输入绑定，以及现有 Console 基线。当前记录中的关卡范围约 X=-4～24.5，需用实时场景核对。

### 3.2 备份策略

- 检查已有 GameScene_Backup 是否涵盖当前状态；可靠且匹配才复用，不能覆盖旧备份。
- 如已有备份早于当前改动，创建唯一名称的当前快照，例如 `GameScene_BeforeSceneRedesign_YYYYMMDD_HHMM.unity`。
- 场景备份不能恢复共享资源。对将修改的 Prefab、材质、纹理 .meta、脚本、ProjectSettings 同时保存变更前副本或可恢复差异与清单。
- 不改变备份中的内容；回滚按清单恢复，不通过删除整个 Assets 目录操作。

### 3.3 素材准备

为选中切片记录源文件、像素矩形、锚点、PPU、用途、碰撞策略。检查透明区域，排除图集色板及占位区域。先用直边、外角、内角和中心块拼一个闭合地形，确认无缝后创建 RuleTile。

优先新增派生资源，避免破坏已有引用。SpriteShape 使用从新素材提取的可平铺填充/边缘，记录来源；轮廓和填充需实际显示。三个包不需要全部素材导入成 Tile，只处理计划使用的部分。

建议产物目录（有同用途结构时复用）：

```text
Assets/Art/Environment/RelicfallRedesign/   派生纹理与材质
Assets/Tiles/RelicfallRedesign/            Tile、RuleTile
Assets/SpriteShapes/RelicfallRedesign/     Profile
Assets/Prefabs/Environment/RelicfallRedesign/
Docs/SceneRedesign/                       基线、素材映射、分阶段验收
```

## 4. Phase 2：样板区制作顺序

1. 在正式场景清理样板区旧纯视觉，保留玩法引用、原顶面与碰撞边界。
2. 铺森林厚土、根系层和石门地基 Tilemap，地形一直延伸到可见底部以下；不用水平拉长的一张地砖冒充地形。
3. 创建可见 SpriteShape 自然崖体，填充连续，与 Tilemap 通过根石独立精灵衔接。
4. 加入接地古树、连续门柱与拱顶、后墙及一组墙边杂物；校对像素锚点。
5. 配置远林与门后暗部、克制的前景、少量灯光。旧灯具若仍引用旧素材，替换其视觉来源。
6. 检查正常镜头下角色、地砖与建筑像素比例；只在证据支持时调整导入设置和相机像素配置。
7. 进入 Play Mode 走过样板区，测试落地、跳跃、冲刺、地面接缝及门口可读性。
8. 保存并交付正常镜头截图、地形厚度检查图和实际对象说明，**停止等待审批**。风格未获认可时只修样板，不扩建全图。

## 5. Phase 3–5：全图实施约束

### 地形与碰撞

- Gameplay 下的控制器、出生点、门、奖励和触发器保留稳定引用。环境按 Grid、SpriteShapes、Environment、Background、Foreground、Lighting 组织，名称不要求中文。
- 地面与平台分别管理；背景填充无碰撞，厚土填充不得封死原有通道或断口。
- Composite 创建顺序与 Tilemap 合并配置必须正确；检查生成路径数量和轮廓，不能仅凭组件存在认定碰撞有效。
- 只迁移确有需要的 Collider，比较迁移前后可站顶面与断口宽度；接触测试覆盖接缝、边缘、冲刺与跳跃落点。

### 支撑与锚点

- 对地面 Props 使用向下射线或地面轮廓采样检查支撑；同时检查可见底部像素，防止透明边框造成误判。
- 顶挂、墙挂、桥梁分别检查接顶点、墙体锚点和两端支座。只靠向下 Raycast 不能证明吊灯与桥梁合理。
- 高台、岩石、柱脚、奖励点逐个检查；背景装饰单独标记，不能让无碰撞背景形成假路线。
- Prefab 实例的位置、缩放、名称等覆盖值正确记录；保存后重新读取位置，防止修改资源后实例回到原点或堆叠。

### 灯光与层次

- 沿用 Background_Far、Background、Environment_Back、Gameplay、Enemy、Player、Weapon、VFX、Environment_Front、UI 层级，必要调整须说明。
- 对 URP 2D 灯光检查 Target Sorting Layers；新环境、角色、武器均应按设计受光，UI 不被环境灯影响。
- 不均匀拉伸背景、明显的 SpriteShape 纹理拉伸、视差露边、像素抖动必须在正常游戏镜头检查。
- 优先共享材质和重复 Prefab，限制可见灯光与粒子；有明显性能回退时再针对定位，不进行无目的大规模优化。

## 6. Phase 6：验收矩阵

| 检查项 | 方法 | 通过条件 |
|---|---|---|
| 三种搭建方式 | Hierarchy/组件 + 画面对应 | Tilemap、SpriteShape、独立精灵均有可见实际贡献 |
| 地形厚度 | 五区镜头、相机边界、结构视图 | 地下连续，底边不露；断口有侧壁和洞腔 |
| 支撑逻辑 | 锚点/射线 + 像素目检 | 无意外悬空树木、柱脚、道具、吊挂件 |
| 路线与 Collider | 基线对比、完整走图 | 原跳距与可站面保持，无卡缝/穿透/假落点 |
| 玩家输入 | Play Mode | W 跳跃、J 攻击；空格/鼠标不再触发这些动作，原移动与冲刺正常 |
| 战斗与奖励 | 实际触发既有遭遇战 | 敌人正常出生、房间封锁/解锁、两波流程与奖励正常，物品可拾取 |
| 角色和 UI | 战斗中目检 | 玩家、敌人、武器、受击反馈与中文 UI 可读，无错误遮挡 |
| 镜头 | 双向走图与边界停留 | 跟随、限制、视差正常，不抖动/露底/错层 |
| Boss/死亡/胜利 | 先查实际实现，再测试 | 已有功能无回退；缺失项明确标为未实现，禁止虚报 |
| Console | 对照实施前基线 | 无本轮新增项目 Error，重要 Warning 有结论；MCP 传输问题单列 |
| 保存持久性 | 保存、重新读取对象与引用 | 引用、Prefab 覆盖、地形与构件位置稳定 |
| 美术效果 | 五区游戏截图 + 全景 + 局部图 | 风格统一、转场自然、战斗留白、无明显拼接与重复焦点；用户确认 |

验证强度按风险选择：纯美术摆位做局部画面与支撑检查；修改脚本时才重新编译；Collider 或引用变化做针对性玩法测试；最终进行一次完整回归。有具体失败才重复相关测试，不反复跑无关测试。

## 7. 每次阶段交付格式

1. 本次完成的 Phase、重建区域和实际截图。
2. 删除的旧视觉、保留的玩法对象、创建/修改的 Tilemap、RuleTile、SpriteShape、Prefab。
3. Collider、灯光、Sorting、相机及共享资源的实际变更。
4. 已执行测试及结果；未测试、未实现、仍需人工确认的内容明确列出。
5. 备份和相关文件路径、下一批范围。
6. 明确停止，不自动进入下一个批次。地图验收完成后同样停止。

## 8. 回滚与异常处理

- 编译或玩法回归失败：先修复当前阶段最小改动，必要时恢复对应资源与场景快照，不触及无关用户改动。
- MCP 断连：核对当前 Unity 状态后继续，避免重复创建同名场景对象。
- 素材不适合预定切片：在同一新素材包内换用合适构件；若必须改变已批准风格或路线，先提交具体差异。
- 无法用现有素材达到认可效果：停在样板验收阶段，报告具体缺口，不能自行换回被否决的旧环境。
